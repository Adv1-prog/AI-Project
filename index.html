🎯 What is the 8-Puzzle Problem?

The 8-Puzzle is a classical state-space search challenge consisting of a $3 \times 3$ grid with 8 numbered sliding square tiles ($1$ to $8$) and one empty slot (represented by _ or 0).

Tiles horizontally or vertically adjacent to the blank space can slide into the empty spot. The goal is to reach a designated target arrangement starting from an initial configuration in the minimal number of tile movements.

Formal Problem Formulation:
  • State Space: All permutations of numbers 0 through 8 ($9! = 362,880$ states, half of which are reachable).
  • Actions: Sliding the blank tile UP, DOWN, LEFT, or RIGHT.
  • Path Cost: Each single tile movement carries a unit cost $c = 1$.

⚖️ Solvability & Inversion Parity

Not all board arrangements can reach an arbitrary target goal! In a $3 \times 3$ grid, a state is solvable if and only if the parity of inversions matches between initial and goal states.

Rule:

An inversion occurs whenever a tile with a greater number precedes a tile with a smaller number (ignoring the blank tile). If Inversions(Start) % 2 === Inversions(Goal) % 2, the puzzle is guaranteed solvable.

Our application automatically checks and validates this mathematical condition in real time before triggering any search algorithm.

📖 Search Algorithm Theoretical Reference

Documentation

1. Breadth First Search (BFS)

Time: O(b^d) Space: O(b^d)

Working Principle: Systematically expands the shallowest unexpanded node across the frontier using a FIFO queue. It explores every node at level k before any node at level k+1.

Advantages: Complete; guaranteed to find the shortest path / minimum moves.
Limitations: High space complexity; exponential memory exhaustion for deep goals.
Completeness: Yes (finite branching).
Optimality: Yes (unit step costs).

2. Depth First Search (DFS)

Time: O(b^m) Space: O(bm)

Working Principle: Explores along each branch as deeply as possible using a LIFO stack before backtracking upon dead ends.

Advantages: Extremely modest memory footprint O(bm).
Limitations: Can get stuck in deep paths; non-optimal.
Completeness: No (unless cycle detection in finite graph).
Optimality: No.

3. Depth Limited Search (DLS)

Time: O(b^l) Space: O(bl)

Working Principle: Executes Depth First Search up to a predetermined depth cutoff limit L.

Advantages: Prevents infinite looping and runaway execution.
Limitations: Incomplete if goal depth d > L.
Completeness: Yes if d <= L.
Optimality: No.

4. Iterative Deepening Depth Limited Search (IDDLS)

Time: O(b^d) Space: O(bd)

Working Principle: Progressively increases the depth limit (0, 1, 2, ... d) executing DLS at each iteration until the solution is discovered.

Advantages: Combines BFS completeness/optimality with DFS linear memory efficiency.
Limitations: Re-generates nodes at upper levels across iterations.
Completeness: Yes.
Optimality: Yes (unit step costs).

5. Greedy Best First Search (GBFS)

Time: O(b^m) worst Space: O(b^m)

Working Principle: Evaluates nodes strictly by their heuristic estimate f(n) = h(n), picking the state estimated closest to the goal.

Advantages: Extremely fast when heuristic guidance is strong.
Limitations: Vulnerable to false paths and local minima; non-optimal.
Completeness: No (without cycle check).
Optimality: No.

6. A* Search

Time: O(b^d) Space: O(b^d)

Working Principle: Evaluates nodes using f(n) = g(n) + h(n), balancing the actual accumulated cost g(n) with the admissible heuristic estimate h(n).

Advantages: Optimally efficient; guaranteed shortest path with admissible heuristics.
Limitations: Stores all generated nodes in memory.
Completeness: Yes.
Optimality: Yes (with admissible h).
